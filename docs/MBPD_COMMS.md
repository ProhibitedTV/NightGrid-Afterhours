# MBPD communications and station refinement
MBPD uses familiar public radio vocabulary adapted for the fictional city: 10-4 (acknowledgment), 10-8 (in service), Code 4 (no additional assistance needed), and brief plain-English incident dialogue. Reference: [City of Tucson public Radio Signal Codes](https://www.tucsonaz.gov/Departments/Police/Radio-Codes). Definitions vary by agency; this is a game-specific selection of routine terms. Dispatch and unit acknowledgments derive from live event sequences, not fabricated reports or real transmissions. Single non-overlapping receiver on WorldSFX, maximum six queued messages, repeat deduplication, caption generated from the same dialogue source as speech, plus bracketed event metadata (not synthesized), and short closure tail. The player hears the channel while wanted or visiting a precinct; no network requests, microphones or real radio access. Local builds without optional generated speech assets fall back to a UI chirp and caption. CI and Windows beta/export generate twelve actual spoken WAV clips using offline eSpeak NG and original radio filtering; no redistribution of recorded voices. For a local full-voice build install espeak-ng and run python3 tools/generate_mbpd_radio.py before Godot import. Original frontage canopy, metal/concrete/PBR details, duty staff with existing idle animation, and live dispatch board in both station rooms. Existing addresses, collisions, room streaming and fleet budget retained. Native audio intelligibility and art review pending. Future: professional voice pack, authored glTF architecture, garage/depot models.

## MBPD service-status vocabulary

| Code | MBPD meaning | Event |
|---|---|---|
| 10-4 | Acknowledged | Unit assignment acknowledgment |
| 10-17 | En route | Same acknowledgment, following assignment |
| 10-19 | Returning to station | Healthy cruiser released to its registered station |
| 10-7 | Out of service | Cruiser retired because of damage or missing station |
| 10-8 | Back in service | Return completed, fleet slot available |
| Code 4 | No more assistance required | Incident closed |

Routine vocabulary references: [Phoenix PD numerical/alphabetical radio codes, March 17 2026](https://www.phoenix.gov/content/dam/phoenix/policesite/mediaassets/Radio%20Codes%20Numerical%20Alphabetical.pdf) (10-17 and 10-7), and [Fountain Valley PD RSVP policies, 2026, p. 15](https://www.fountainvalley.gov/DocumentCenter/View/23968/RSVP-POLICIES-AND-PROCEDURES-2026pdf) (10-19). MBPD is a fictional local codebook; definitions differ across agencies. The damaged unit event never creates a return or arrival announcement. No dispatch routing or wanted-level behavior is changed.

## Queue closure behavior
Code 4 takes priority over queued radio traffic after the currently playing clip. Pending report/assignment/acknowledgment/contact/search lines are discarded when the incident closes, and release bursts cannot evict the pending closure. The receiver drains closing traffic for up to 20 seconds outside a station, then goes quiet; unrelated later availability is not guaranteed to be audible. No change to pursuit logic, heat, or station capacity.

## Independent civic service ledger (phase 3A)
The world owns `ambient_civic` (`scripts/ambient_civic_ledger.gd`), separate from wanted and player dispatch. Every 20 naturally elapsed game minutes a seeded fictional service request is created at an authored civic site's street-side staging point, assigned to the nearest registered station by road distance at initialization. An abstract case is queued for five minutes, active until minute 18, then resolved; at most two recent cases are retained for 40 minutes. These are simulated administrative states, not claims that a visible officer has reached a location. The public board shows the count of outstanding civic cases. `catalog()` returns defensive copies of ID, kind, state, site/station IDs, district, point and creation minute; `open_count()` returns non-resolved cases. #80 must add physical assignment/arrival and completion semantics before treating this as a vehicle task; #81 adds matching dialogue only after these events exist. No player heat, real radio, response-unit allocation or fabricated player witnesses. The optional v1 save field stores elapsed minute/fraction; seed and authored sites reconstruct cases. Old/invalid optional fields reset the ledger. Natural fixed-tick time stops with the day clock; manual debug clock jumps do not fast-forward cases. Changing the authored site catalog in future releases can change reconstructed locations. Native validation pending.

## Civic request notices (first part of #81)
Inside headquarters, or the precinct responsible for a current civic request, the existing receiver can announce a motorist assistance, traffic service or public service request on file. The caption includes the actual case ID, district and station; it does not assert a physical unit arrival or resolved scene. No routine notice while player heat/closing traffic is active or the day clock is paused. One notice per retained case per loaded session, only when the receiver is otherwise idle; no extra simultaneous audio voices. On reload the notice may replay once. Outside station rooms the existing wanted receiver behavior is unchanged. Physical patrol acknowledgments, localized exterior radio, accessible dedicated audio controls and native review remain #80/#81 work.

## Physical civic patrol pilot (part of #80)
One existing jurisdiction-matched routine cruiser can claim an ACTIVE administrative request when player heat is zero. A separate scene-independent task tracks EN_ROUTE/SERVICING, with a 100-second travel timeout and six-second stationary dwell. The original road controller drives; no siren priority, new cars, or fabricated witnesses. Administrative request expiry does not imply physical arrival or completion: the claimed task has its own lifecycle, shown separately on the board. Arrival requires actual vehicle position, speed and road-controller arrival. In-flight tasks are safely cancelled on scene reload; recent handled IDs persist to prevent duplicate assignment. Restoring a claim at a fake position is avoided. New smoke exercises real cruiser assignment and a controlled arrival fixture, not autonomous native traversal. Curb clearance, physical scene props, blocked-lane recovery, native actual arrival and radio lifecycle messages remain open #80/#81/#88.
